# x402: pay-per-score

hood-oracle sells one thing over [x402](https://github.com/coinbase/x402):
its verdict on a launch. `GET /api/x402/score/:token` answers `402 Payment
Required` until the request carries a signed USDG payment on Robinhood Chain
(chain id 4663), then returns the latest `OracleVerdict`, the 90-second
feature snapshot and the latest firewall round trip. The rail is
[hood402](https://www.npmjs.com/package/hood402): USDG (Paxos Global
Dollar) over the x402 `exact` scheme, settled with an EIP-3009
`transferWithAuthorization`, so the buyer signs once and never pays gas.

Everything else stays free: the feed, the coin page, the streams, the
dashboard. The paid route exists for agents and services that want one
verdict on demand without running an engine.

## For buyers

### Discover the price

```bash
curl -s https://<engine>/api/x402/pricing
```
```json
{
  "enabled": true,
  "resource": "https://<engine>/api/x402/score/:token",
  "method": "GET",
  "price": { "usdg": "0.05", "atomic": "50000", "decimals": 6 },
  "network": { "id": "robinhood", "chainId": 4663 },
  "asset": { "symbol": "USDG", "address": "0x5fc5360D0400a0Fd4f2af552ADD042D716F1d168", "eip712": { "name": "Global Dollar", "version": "1" } },
  "scheme": "exact",
  "x402Version": 1,
  "payTo": "0x...",
  "facilitator": "https://facilitator.hood402.dev",
  "description": "hood-oracle conviction verdict for one Robinhood Chain launch: ...",
  "freeAlternative": "https://<engine>/api/oracle/feed",
  "howToPay": "GET the resource; a 402 carries `accepts[]`. ..."
}
```

`enabled: false` means the operator has not set a pay-to address; the paid
route answers 503 and nothing here can be bought.

### The handshake

1. `GET /api/x402/score/0x9a1...` with no payment. A scored token answers
   `402` with the x402 v1 body:

   ```json
   {
     "x402Version": 1,
     "accepts": [ {
       "scheme": "exact",
       "network": "robinhood",
       "maxAmountRequired": "50000",
       "resource": "https://<engine>/api/x402/score/0x9a1...",
       "description": "hood-oracle conviction verdict ...",
       "mimeType": "application/json",
       "payTo": "0x...",
       "maxTimeoutSeconds": 60,
       "asset": "0x5fc5360D0400a0Fd4f2af552ADD042D716F1d168",
       "extra": { "name": "Global Dollar", "version": "1" }
     } ]
   }
   ```

2. Sign an EIP-3009 `TransferWithAuthorization` for `maxAmountRequired`
   atomic USDG (6 decimals) from your wallet to `payTo`, with a fresh random
   32-byte nonce and a short validity window, under the USDG EIP-712 domain
   (`name` and `version` from `extra`, chain 4663, the `asset` contract).
3. Retry the same `GET` with `X-PAYMENT: <base64 JSON payload>` (the
   standard x402 `PaymentPayload`: `{ x402Version, scheme, network, payload: { signature, authorization } }`).
4. The engine asks the facilitator to verify (structure, signature, nonce
   not yet used, balance) and settle (broadcast the transfer). On success it
   answers `200` with the verdict and `X-PAYMENT-RESPONSE: <base64 receipt>`
   carrying the settlement transaction hash. On failure it answers `402`
   again with an `error` string saying why (expired, insufficient balance,
   replayed nonce, wrong network).

Two guarantees about ordering: a token that was never scored answers `404
not_scored` (pointing at the free feed) **before** any payment is asked
for, and a settlement that fails never returns the resource. You pay only
for a verdict that exists, and only once it has settled.

### Pay with the SDK or with hood402

```ts
import { createClient } from '@hood-oracle/sdk'
import { privateKeyToAccount } from 'viem/accounts'

const hood = createClient({ baseUrl: 'https://<engine>' })
const account = privateKeyToAccount(process.env.PAYER_PRIVATE_KEY as `0x${string}`)
const { data, settlement } = await hood.x402.score('0x9a1...', { account, maxSpendUsdg: '0.50' })
console.log(data.verdict.score, data.verdict.tier, data.firewall?.verdict, settlement?.transaction)
```

Or with hood402's client directly, which pays any x402 challenge it meets:

```ts
import { Hood402Client, fromAccount } from 'hood402/client'

const client = new Hood402Client({ signer: fromAccount(account), maxSpendPerOrigin: '1.00' })
const res = await client.fetch('https://<engine>/api/x402/score/0x9a1...')
console.log(await res.json())
```

The payer's wallet needs USDG on Robinhood Chain and no ETH. Both clients
enforce a per-origin spend cap and refuse to sign above it.

### What you get

```json
{
  "token": "0x9a1...",
  "verdict": { "id": "...", "score": 78, "tier": "strong", "rugRisk": 0.09, "probabilities": { "win": 0.31, "rug": 0.09, "moon": 0.52 }, "pillars": { ... }, "hits": [ ... ], "reasons": [ ... ], "confidence": 0.92, "modelVersion": "v3-...", "scoredAt": "..." },
  "features": { "token": "0x9a1...", "observedAt": "...", "windowSeconds": 90, "features": { "unique_buyers": 47, "...": "..." }, "missing": [] },
  "firewall": { "verdict": "allow", "score": 96, "roundTripLossPct": 0.021, "checks": [ ... ], "assessedAt": "..." },
  "history": 3,
  "paidAt": "..."
}
```

`firewall` is null until the engine has simulated a round trip on the
token (it does so before every live buy). `history` counts every verdict
the token has received; the free `GET /api/oracle/coin/:token` lists them.

## For operators

| Env var | Default | Meaning |
|---|---|---|
| `X402_PAY_TO` | unset (route disabled) | The address USDG payments are sent to. Any 0x address you control; a plain EOA is fine. Setting it enables the route on the next start. |
| `X402_SCORE_PRICE_USDG` | `0.05` | Price of one verdict in USDG, up to 6 decimals. |
| `X402_FACILITATOR_URL` | `https://facilitator.hood402.dev` | The hood402 facilitator that verifies signatures and broadcasts settlement. Run your own with the `facilitator/` service in the hood402 repo and point this at it. |

With `X402_PAY_TO` unset, `/api/x402/pricing` reports `enabled: false` and
`/api/x402/score/:token` answers `503 x402_not_configured`; nothing else
changes. There is no key to manage on the engine: the facilitator holds
the gas wallet, the engine only relays signed authorizations, and the
buyer's signature fixes the amount and recipient so neither can be
changed in flight.

### Settlement

The facilitator broadcasts `transferWithAuthorization` on USDG and waits
for the receipt before the engine serves the verdict. Every payment is a
separate on-chain transfer to `X402_PAY_TO`; there is nothing to withdraw.
Watch the address on [Blockscout](https://robinhoodchain.blockscout.com)
or read `hood_x402`-free logs: the engine logs `x402 score sold` with the
token, the payer and the transaction hash at info level, and
`x402 settlement failed` with the facilitator's reason at warn level.

If the facilitator cannot be reached, the route answers `502
facilitator_unreachable` naming the URL; nothing is charged. Replays are
refused twice: the facilitator checks the nonce on-chain
(`authorizationState`) and keeps an idempotent ledger keyed by `(network,
payer, nonce)`.

### Rate limits and the paid route

The paid route is a read for rate-limiting purposes (600 per minute per
client address by default), which is far above what settlement latency
allows anyway.

## Testing

`tests/hardening.test.ts` asserts the 402 challenge shape from the real
hood402 middleware (scheme, network, USDG asset, atomic price, pay-to,
resource, EIP-712 domain), the 404 for an unscored token, the 503 when
unconfigured, and the 402 re-challenge on a malformed `X-PAYMENT`.
`tests/sdk.test.ts` drives the SDK helper through a real signature up to
the facilitator boundary.
